## 模块划分

### 前端 (frontend/)

| 模块 | 文件 | 职责 |
|------|------|------|
| 配置 | `js/config.js` | 前端全局配置（API 地址、轮播间隔等） |
| 时钟 | `js/clock.js` | 实时显示年月日+星期+时分秒 |
| 天气 | `js/weather.js` | 请求后端天气 API，渲染天气信息 |
| 轮播 | `js/slideshow.js` | 图片列表获取、自动轮播、手动切换、预加载 |
| 样式 | `css/style.css` | 全屏布局、按钮样式、过渡动画、iPad 适配 |

### 后端 (server/)

| 模块 | 文件 | 职责 |
|------|------|------|
| 入口 | `src/index.js` | Express 服务启动、静态文件服务、路由注册 |
| 配置 | `src/config.js` | 服务端配置（路径、缓存、天气 API） |
| 照片 API | `src/routes/photos.js` | 递归扫描目录、图片文件服务、缓存 |
| 天气 API | `src/routes/weather.js` | 代理和风天气 API、缓存 |

### 基础设施

| 组件 | 说明 |
|------|------|
| Nginx | 反向代理，静态文件缓存，API 转发 |
| Docker | 容器化部署，Nginx + Node.js 双容器 |
| 群晖 NAS | 照片存储，通过 Volume 挂载到容器 |

## 数据流

### 照片轮播流程

```
1. 前端请求 GET /api/photos
2. 后端扫描 NAS 照片目录（递归遍历子目录）
3. 返回图片 URL 列表（如 /api/photos/2024/IMG_001.jpg）
4. 前端依次加载图片，自动轮播
5. 用户点击 ◀ ▶ 按钮手动切换
```

### 天气获取流程

```
1. 前端请求 GET /api/weather
2. 后端检查缓存（30分钟有效）
3. 缓存未命中 → 请求和风天气 API
4. 返回天气数据给前端渲染
```

## 技术选型

| 层级 | 技术 | 选型理由 |
|------|------|---------|
| 前端框架 | 原生 HTML+CSS+JS | 零依赖，适配老 iPad 低内存 |
| UI 框架 | Tailwind CSS (CDN) | 快速布局，按需加载 |
| 后端 | Node.js + Express | 轻量，Docker 镜像小 |
| 天气 API | 和风天气 | 免费，国内访问快 |
| 容器化 | Docker + Compose | 群晖原生支持 |
| 反向代理 | Nginx | 高性能静态文件服务 |

## 异常处理

| 场景 | 处理方式 |
|------|---------|
| 天气 API 失败 | 隐藏天气模块，不影响相册和时钟 |
| 图片加载失败 | 自动跳过，尝试下一张 |
| 照片目录不存在 | 显示占位提示，不崩溃 |
| 路径穿越攻击 | 后端校验 resolvedPath 必须在照片目录内 |
